Three ways to change a component, in the order worth trying them.

## Use Props

Props are the reliable way to change a component, because the component applies them itself.

```tsx
<Badge tone="subtle" color="green" size="lg" shape="pill">
  Shipped
</Badge>
```

Every component page lists its full API: each prop, its type, its default and what it does. Reach for that table before anything else. Most of what people try to do with `className` already exists as a prop.

## className

Every component takes `className` and merges it into its own classes.

```tsx
<Button className="w-100%">Save</Button>
```

That works for adding something the component does not set, like width above, and it works for overriding something it does set.

```tsx
<Button className="c-accent">Save</Button>
```

Yumma CSS utilities are all single-class selectors, so they all have the same specificity, and the winner between two of them is whichever comes later **in the generated stylesheet**. Adding `c-accent` to a component that already sets `c-white` used to do nothing at all. Components call [`merge`](/docs/class-merge) instead of appending, which drops the class that loses, so what you pass takes effect.

Only a class that sets the same property is dropped, so nothing you add goes missing.

<Hint icon="info">
  Reach for a prop first anyway. It says what you mean, it is checked, & it
  survives an edit to the component's own classes.
</Hint>

When there is no prop for what you need, edit the file.

## Own Your Components

`yummaui add` copies a real file into your project, and nothing overwrites it later. When props and `className` are not enough, all you need to do is edit it.

Components are built on [Base UI](https://base-ui.com), so the primitive underneath is documented there, which matters the moment you start editing. Pages built on a primitive link to it directly.

Removing a component you decided against is [`yummaui prune`](/ui/components/cli#prune).

## Colors & Theme

Component colors come from Yumma CSS, so they are configured in `yumma.config.mjs` rather than anywhere in Yumma UI. Adding a brand color or changing how shades are generated is covered in [Colors](/docs/colors) and [Configuration](/docs/configuration).
